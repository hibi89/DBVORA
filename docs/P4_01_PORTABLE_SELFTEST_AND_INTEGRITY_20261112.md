# P4-01 — Portable archive self-check, extracted source integrity and browser QA

**2026-11-12 KST · target milestone DBVORA 85% provisional engineering · RELEASE HOLD**

## Alternatives / rationale
- A: ship unsigned developer ZIP and rely on user/Windows to infer backup correctness. Lowest implementation time, but no runtime archive regression or post-extraction tamper check; rejected.
- B: ship a deterministic, no-network developer preview with an **explicit synthetic-only full-engine selfcheck**, SHA-256 checks of extracted package files, Windows/Unix launchers, and Chromium document-only QA. Selected because it reuses existing ZIP/ZSTD engines/ledger/recovery audit and does **not** execute customer backups or require additional API/pip services. SHA manifest remains unsigned and can be forged along with source, so this is neither authentication nor certified release.

## Features
1. `dbvora/archive/review_selftest.py` in packaged `dbvora`: executable `python -m dbvora.archive.review_selftest`, **no external arguments or DB paths accepted**. Creates isolated OS temp SQLite with parent/child rows; original SQLite snapshot -> request ledger -> ZIP (and local ZSTD if present) -> actual `restore_zip_archive`/`restore_zstd_archive` to a new output -> content digest and SQLite integrity -> independent catalog/ledger audit -> owner-readable offline review HTML -> exact request replay must HOLD -> intentionally corrupts **only a generated temporary archive** -> verified state must change to `RECORDED_NOT_VERIFIED`. Source/snapshot hash/size/mtime unchanged. Emits fixed-code, path-free JSON and false customer/power-loss claims.
2. `dbvora/archive/portable_verify.py` in packaged source: `python -B -m dbvora.archive.portable_verify`, no user paths. Reads exact `MANIFEST.sha256.json` from the extracted package root, checks bounded file counts/sizes/SHA, rejects missing/mutated source, path traversal, symlink parent/manifest/code, unlisted executable source (and symlinks even in pycache). **Unsigned source integrity only**; cannot prove publisher identity or prevent a forged manifest+files. Does not read customer DBs or delete anything.
3. `scripts/build_portable.py`: retains deterministic create-only unsigned source ZIP and adds no-argument `check_dbvora_archive_windows.cmd`, `check_dbvora_archive_unix.sh`, `verify_dbvora_portable_windows.cmd`, `verify_dbvora_portable_unix.sh`. All generated by the existing builder and included in its required manifest. `README_PORTABLE.txt` distinguishes selfcheck, source verification and lack of publisher/NTFS safety claims.
4. Added tests: `tests/test_review_selftest.py` (14), `tests/test_portable_verify.py` (15 including cache symlink), new `tests/test_portable_build.py` extracted-source and tamper tests (5), `tests/test_request_ledger.py` record-only SQLite `mode=rw` race test (1). `scripts/verify_release_gate.py` Python minimum **553** and REQUIRED updated; existing test fixtures synchronized. No skip/excluded-test decrease.
5. Optional `scripts/review_html_browser_probe.py`: runs actual report renderer in local headless Chromium, document-only `set_content`, 12 checks of Korean accessibility/table/CSP/no approval UI/no external requests/no JS errors. Explicit `browser_native_file_url_verified=false`.

## Design comparison and decision
**Option A — retain full redraw per selection.** Each click walked all table controls, regenerated all SVG paths and measured graph geometry for each FK. Render inserted every card individually. Pros: simplest immediate behavior; cons: repeated layout work and large-dom churn even if only highlight changes.
**Option B — cache visible edges and batch cards.** Add `edgeByTable` adjacency of rendered SVG paths; table selection updates previous/new button `aria-pressed` and only incident path CSS classes, not the SVG tree. During filter/resize, rebuild visible paths once, cache each node rectangle once, and append SVG paths as a batch; build 1,000 table buttons then one batch append. Prefer **B**: same visible behavior and text-node-only schema escaping, no new libraries, no API calls, no subscription or server change. This choice is not a guarantee on older hardware.
